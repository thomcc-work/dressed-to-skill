# Holistic writing

Write for readers without the originating conversation, investigation, or design session.
Establish the context for writing or reviewing the complete text, then use the shared editorial pass.

## Scope and authority

The task and any specialized skill establish what may change; an editorial pass does not expand that permission.
A review request does not authorize prose edits.
For review-only work, report findings, evidence, consequences, and the smallest useful corrections.
If the user has not said what to write, establish the intended reader, purpose, and form before drafting.
Ask when missing context would materially change the result rather than inventing the audience or assuming permission that was not granted.

When another skill covers the requested writing or review, start there rather than running this workflow separately.
Those skills link directly to the [shared editorial pass](references/editorial-pass.md) and say when to use it.
An editorial-only request can start here when the skill for that type of text does not cover that review.
Reuse established decisions rather than restarting their workflows.
For documentation-specific reader tasks, forms, prerequisites, commands, links, and workflow checks, use [Documentation](references/documentation.md).
Follow [Documentation conventions and placement](../references/documentation-placement.md)
for documentation, prose source, and agent instructions, even when the destination is already known.
A small addition or new heading does not require a review of the complete text.

Use these other skills only for the tasks they cover, not as compulsory stages of this pass:

- `readme-writing` owns introductory README writing and review, not every file named README.
- `reorganize-docs` owns existing documentation trees, page splits, renames, consolidation, and navigation.
- `requirements-definition` owns requirements authoring from established goals and authoritative sources.
- [Spec review](../spec-review/SKILL.md) checks whether specification requirements agree, can be traced to their sources, introduce unsupported restrictions, and include what is needed at the current stage.
- `skill-authoring` covers decisions about what skills do, how agents find them, and which steps they require; this skill improves their written presentation without silently changing those decisions.
- `tighten-prose` polishes specified sentences and paragraphs within an established explanation.

If a needed skill is unavailable, keep its decisions outside this task, state the limitation, and do not claim that its review occurred.

## 1. Establish what to write or review

For direct authoring or review, establish any missing reader, purpose, requirements, and factual evidence.
Use the brief, relevant entry points, authoritative inputs, and representative uses.
For creation, inspect the material the new text must explain and any established destination or form.

If another procedure has already established this context, reuse it.
Do not reconstruct the investigation or reopen settled design decisions.

## 2. Use the shared editorial pass

Read and follow the [editorial pass](references/editorial-pass.md) with the text and established context, preserving the distinction between permission to write and permission only to review.
It covers explanatory development, reading experience, factual fidelity, revision, and validation through completion.
The task and specialized skills still govern what may change; starting here does not make their workflows compulsory editorial stages.
